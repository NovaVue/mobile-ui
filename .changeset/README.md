# Changesets

Hello and welcome! This folder has been automatically generated by `@changesets/cli`, a build tool that works
with multi-package repos, or single-package repos to help you version and publish your code. You can
find the full documentation for it [in our repository](https://github.com/changesets/changesets)

We have a quick list of common questions to get you started engaging with this project in
[our documentation](https://github.com/changesets/changesets/blob/main/docs/common-questions.md)

# 使用方法
```shell
# 选择版本号策略
# 输入更新摘要
npx changeset

# commit文件，包括本次的代码修改和生成的changelog文件
git commit .

# 生成 changelog
npx changeset version

```

# Changeset 版本号规则配置指南

Changeset 提供了灵活的方式来控制包版本号的更新规则。以下是配置版本号规则的详细方法。

## 1. 基本版本号规则设置

### 通过 changeset 文件指定

在创建 changeset 时可以直接指定版本更新类型：

```bash
# 交互式选择版本类型
npx changeset

# 或直接指定
npx changeset --semver [major|minor|patch]
```

在生成的 `.changeset/*.md` 文件中会包含类似内容：

```markdown
---
"package-name": patch
---
```

## 2. 全局版本规则配置

在 `.changeset/config.json` 中设置默认规则：

```json
{
  "version": {
    "mode": "default", // 或 "independent"
    "strategy": "fixed" // 或 "linked"
  }
}
```

## 3. 版本模式配置

### 固定模式 (Fixed - 默认)

所有包版本同步更新：

```json
{
  "fixed": [["pkg-a", "pkg-b"]],
  "version": {
    "mode": "default"
  }
}
```

### 独立模式 (Independent)

每个包独立版本：

```json
{
  "version": {
    "mode": "independent"
  }
}
```

## 4. 版本更新策略

### 更新内部依赖的规则

```json
{
  "updateInternalDependencies": "patch" // 或 "minor"
}
```

- `"patch"`: 只更新补丁版本
- `"minor"`: 更新次要版本

## 5. 预发布版本配置

```json
{
  "command": {
    "version": {
      "preid": "beta",
      "prerelease": true
    }
  }
}
```

## 6. 自定义版本解析

创建自定义版本策略文件 `versionStrategy.js`:

```javascript
module.exports = function versionStrategy(releases, dependenciesUpdated) {
  return {
    ...releases,
    "pkg-a": "minor" // 强制特定包使用minor
  };
};
```

然后在配置中引用：

```json
{
  "version": {
    "strategy": "./versionStrategy.js"
  }
}
```

## 7. 按条件控制版本

在 changeset 文件中使用条件语法：

```markdown
---
"pkg-a": minor if dependenciesUpdated
"pkg-b": patch unless peerDependenciesUpdated
---
```

## 8. 版本号范围限制

限制特定包的版本更新范围：

```json
{
  "constraints": {
    "pkg-a": {
      "maxVersion": "2.x",
      "minVersion": "1.2.0"
    }
  }
}
```

## 9. 版本更新钩子

在版本更新前后执行自定义逻辑：

```json
{
  "hooks": {
    "preVersion": "npm run test",
    "postVersion": "git push --follow-tags"
  }
}
```

## 10. 完整配置示例

```json
{
  "$schema": "https://unpkg.com/@changesets/config@2.0.0/schema.json",
  "changelog": "@changesets/cli/changelog",
  "commit": false,
  "fixed": [["pkg-a", "pkg-b"]],
  "linked": [["pkg-c", "pkg-d"]],
  "access": "public",
  "baseBranch": "main",
  "version": {
    "mode": "default",
    "strategy": "fixed",
    "preid": "beta",
    "prerelease": false
  },
  "updateInternalDependencies": "patch",
  "ignore": ["@internal/*"],
  "constraints": {
    "pkg-a": {
      "maxVersion": "2.x"
    }
  },
  "hooks": {
    "preVersion": "npm run test"
  }
}
```

## 最佳实践

1. **大型项目**：使用独立版本模式 (`"mode": "independent"`)
2. **UI组件库**：使用固定版本模式确保组件同步更新
3. **工具链**：配置 `updateInternalDependencies: "minor"`
4. **预发布**：设置 `preid: "alpha"` 或 `preid: "rc"`

通过合理配置这些规则，可以精确控制项目中每个包的版本更新策略，满足不同的发布需求。
